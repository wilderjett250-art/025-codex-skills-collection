# 全局规则与 Skill 成本审计

日期：2026-10-11。对象：个人全局规则、个人 Skill 库和本地便携仓库；不含系统/官方插件 Skill 的逐项优化，也不是所有工具的真实任务验收。

## 当前规则

全局规则分为十个约束面：任务/权限/完整交付、独立判断、写入前恢复点、备份保留、工具与故障恢复、证据与交接、上下文与 Skill 路由、知识与秘密、Windows/存储、生成物保留。

默认先检查当前可用 Skill；没有合适入口再检索冷库元数据，比较最多三个候选，加载当前工作单元的专项入口。只有当前步骤需要才读条件参考。领域 owner 和访问工具分开；并非默认加载七类产品/工程流程。原有 300 个名称和 canonicalPath 均保留，新增 HTML 后为 9 常驻 + 292 按需，共 301 个。

本轮精简没有降低模型推理档，也没有修改权限、账号或 MCP 启停配置。采用短入口、条件参考、可重复脚本和有界工具结果来降低浪费；图文页不是 always-on。

之前重点升级的常用入口约 361–621 token：大项目、产品、UI 打磨、架构、React、应用性能、代码审查、验收策略。这些数字不含被当前操作实际需要的参考。

全库结构审计覆盖 301 个个人入口，检查名称、路径、体积及显式 `references/...` Markdown 链接；未发现这类链接缺失。存在一个已有外部目录链接的 browser Skill，保留并标记，不误报为缺失或修改真实浏览器桥接。

仍有 85 个入口超过 8,000 字符，26 个超过 16,000 字符。最大的几个包括旧 Artifact Excel、交互式 Playwright 和旧专业演示工作流。长不一定低质，但触发后成本高；它们没有全部逐条重写或做真实应用任务评测。不能把结构测试或热门来源当作“301 个都好用”的证明。

## 两个项目吸收了什么

- [Windows-MCP Snapshot 源码](https://github.com/CursorTouch/Windows-MCP/blob/b74c507d9e709223a0904cf08019edf55f2a75bb/src/windows_mcp/tools/snapshot.py)：UIA 文字优先、按区域/显示器观察、需要视觉证据时截图、界面变化后重新定位。写入操作 Skill 的条件参考和 Windows 测试入口。没有安装/启用服务器或接管桌面；文本树不替代视觉验收。
- [Answer me with HTML](https://github.com/QingYunA/answer-me-with-html/tree/533c39fd47d814a6bee3d9c1df388345f4e4c858)：复用 MIT 本地渲染器，让模型写内容和结构，程序处理布局、CSS、SVG。保留许可证和版本/哈希，使用短且窄的入口；不抄 always-on、宽泛触发、后台更新或自动打开浏览器。
- [作者基准](https://github.com/QingYunA/answer-me-with-html/blob/533c39fd47d814a6bee3d9c1df388345f4e4c858/bench/README.md)：“约八倍”来自固定语料的输出体积比较，不是我们本机的计费节省。实际输入、缓存、额外轮次和页面内容不同都会改变总成本；本轮未复现付费模型 A/B 测试。

HTML 包装器拒绝已有输出、原始 HTML/SVG、图片及源文件嵌入；禁用浏览器打开/更新检查，输出增加禁止联网的内容策略。它不是通用安全沙箱，不用于执行不可信网页、读私有代码或启动局域网服务。生成文件、路由成功和作者统计都不是事实正确性的证明。

## 规则保留检查

这是逐约束面的人工对照，不声称自然语言语义已被自动证明：

| 约束面 | 保留的关键边界 |
|---|---|
| 任务与授权 | 项目根、外部变更审批、用户指定技术/算法、目标版本与发布阶段、完整链路交付、单一关键问题 |
| 独立判断 | 不迎合、证据与推断分开、具体反证、适用时检查偏差/依赖/二阶影响 |
| 恢复点 | 首写前、脏/未跟踪内容及元数据、数据库副作用与准确行、生产写测单独权限、恢复验证、事故冻结 |
| 保留策略 | 同项目/环境/范围一套可恢复备份、验证后再轮换、只删清单允许项、用户/其他任务/PITR 不混删 |
| 工具 | 按需恢复可信资源禁用、真实 callability、保留指定浏览器、可能已成功写入先核对、恢复阶梯、真实可见人工门槛 |
| 验收 | 同因果链证据、区分实现/静态/构建/运行/上传/部署/设备、复发撤回旧结论、真实截图、唯一交接 |
| 路由 | 可用能力先选、一次针对性冷库查找、原子 owner、阶段切换、读取器元数据记录、详情非整包常驻 |
| 知识与秘密 | 采集默认关、历史导入单独授权、图像证据注记非知识入库、推断不混事实、秘密不输出/发布 |
| Windows/存储 | PowerShell、I 优先 G 次选、系统文件原位维护、桌面接管明确授权 |
| 生成物 | 明确版本族留三版、再生物与证据/源/依赖分开、范围不明先确认 |

## 验证及边界

- 原有检索：34 条任务、86 项检查通过；七类能力：21 条命中、6 条边界、3 条 CLI 和 2 项目录约束通过；原词法路由 98 项和活动记录 4 项通过。
- 新上下文检查 17 项、HTML 渲染/保护 16 项通过。Windows 原指南 18 个片段可逐字节重组，渲染器哈希与固定上游一致；四个变更 Skill 通过结构校验。
- 实际本地页面在独立、无登录会话的 headless Edge 中以 1440/768/390 宽度渲染并查看截图；没有页面级溢出、外部请求或页面脚本异常。首版横向图在窄屏需滚动，改为短标签/纵向图后重新检查。该验证只证明这个说明页，不证明所有未来页面或 Windows 桌面操作。
- 程序生成图文页不需模型重写排版，但本轮没有真实业务效果、自动模型选中率、全库质量或总费用 A/B 的证据。不得把这些检查扩大为未执行的验收。
- 最终便携包在 Windows PowerShell 5.1 中独立安装为 9 + 292；新检查 17 项、渲染保护 16 项、原搜索 86 项与七类能力 21 条仍通过，全局规则/Hook 再次安装没有追加写入。渲染器附带原项目及 Dagre/Graphlib/Marked 的许可文件与哈希；独立目录只做安装验证，没有调用用户账号或 MCP。

依据：[OpenAI 关于精确描述与渐进式加载的说明](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。个人全局规则和本机配置依然应按目标电脑实际情况审查；便携设置快照不是强制默认权限。
