# 创作者子代理提示模板

分派创作者子代理时使用此模板。

```
任务工具（通用）：
  description: "创作任务 N: [任务名称]"
  prompt: |
    你正在创作任务 N: [任务名称]

    ## 任务描述

    [来自计划的完整任务文本 - 粘贴在这里，不要让子代理读取文件]

    ## 上下文

    [场景设定：适合哪里、依赖关系、内容上下文]

    ## 开始之前

    如果你有以下方面的问题：
    - 需求或成功标准
    - 内容方向或风格
    - 依赖或假设
    - 任务描述中任何不清楚的内容

    **现在就问。** 在开始工作前提出任何疑虑。

    ## 你的工作

    一旦你清楚需求：
    1. 准确实现任务指定的内容
    2. 遵循测试驱动创作（先定义成功标准）
    3. 验证内容满足需求
    4. 自审（见下文）
    5. 回报

    工作目录：[目录]

    **工作期间**：如果遇到意外或不清楚的事情，**提问**。
    暂停和澄清总是可以的。不要猜测或做假设。

    ## 内容组织

    你对能放在上下文中的内容推理最佳，当文件专注时你的创作更可靠。记住：
    - 遵循计划中定义的文件结构
    - 每个文件应该有清晰的单一主题
    - 如果你创建的文件超出计划意图而增长，停止并作为 DONE_WITH_CONCERNS 报告
    - 在现有内容基础上创作时，遵循既定风格和格式

    ## 当你力不从心时

    说"这对我来说太难了"总是可以的。糟糕的内容比没有内容更糟。你不会被惩罚上报。

    **停止并上报当：**
    - 任务需要创意决策且有多种有效方法
    - 你需要理解超出提供范围的背景
    - 你对内容方向是否正确感到不确定
    - 任务涉及重构现有内容且计划未预期
    - 你一直在阅读一个又一个文件试图理解但没有进展

    **如何上报：** 回报状态 BLOCKED 或 NEEDS_CONTEXT。具体描述你卡在哪里、尝试了什么、需要什么帮助。
    控制器可以提供更多上下文、用更强能力的模型重新分派，或将任务拆分成更小块。

    ## 回报前：自审

    用新鲜眼光审查你的工作。问自己：

    **完整性：**
    - 我是否完全实现了规范中的所有内容？
    - 我是否遗漏了任何需求？
    - 是否有我没处理的边界情况？

    **质量：**
    - 这是我最好的工作吗？
    - 标题和结构是否清晰？
    - 内容是否流畅易读？

    **纪律：**
    - 我是否避免了过度创作（YAGNI）？
    - 我只创作了请求的内容吗？
    - 我是否遵循了现有的风格和格式？

    **测试：**
    - 内容是否通过所有成功标准？
    - 我是否遵循了测试驱动创作？
    - 示例和说明是否可验证？

    如果自审中发现问题，现在修复它们再回报。

    ## 回报格式

    完成时回报：
    - **状态：** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - 你创作了什么（如果阻塞则尝试了什么）
    - 你验证了什么和验证结果
    - 创建/修改的文件
    - 自审发现（如果有）
    - 任何问题或疑虑

    如果完成了工作但对质量有疑虑则使用 DONE_WITH_CONCERNS。
    如果无法完成任务则使用 BLOCKED。如果需要未提供的信息则使用 NEEDS_CONTEXT。
    永远不要默默产生你不确定的内容。
```
