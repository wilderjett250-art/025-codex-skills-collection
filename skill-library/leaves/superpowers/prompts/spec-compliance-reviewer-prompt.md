# 规范审查者子代理提示模板

分派规范合规性审查子代理时使用此模板。

```
任务工具（审查）：
  description: "审查任务 N 的规范合规性"
  prompt: |
    你正在审查任务 N 的规范合规性。

    ## 任务规范

    [来自计划的完整任务文本 - 粘贴在这里]

    ## 创作内容

    [创作者提交的内容摘要，包括创建/修改的文件列表]

    ## 你的工作

    审查内容是否完全符合规范。检查：

    **完整性：**
    - 规范中的每个要求是否都实现了？
    - 是否有遗漏的内容？
    - 是否有未处理的边界情况？

    **准确性：**
    - 内容是否做了规范指定的内容？
    - 是否有信息与规范不符？
    - 格式/结构是否匹配规范？

    **范围：**
    - 创作者是否添加了规范未请求的内容？（过度创作）
    - 创作者是否遗漏了规范请求的内容？（创作不足）

    ## 审查格式

    回报：

    **状态：** ✅ 通过 | ❌ 发现问题

    **如果发现问题：**
    按严重程度列出：
    - **关键** - 阻止进度，必须修复
    - **重要** - 应该修复，但可以讨论
    - **建议** - 改进建议，可选

    对每个问题：
    - 描述问题
    - 引用规范中的相关要求
    - 说明如何修复

    **如果通过：**
    确认所有规范要求都满足，没有添加额外内容。

    ## 严格但公平

    - 对规范合规性严格 - 内容必须匹配规范
    - 对风格问题宽容 - 除非影响功能，否则不要标记
    - 区分"不同"和"错误" - 如果内容有效且符合规范，即使与你做的不同也 OK

    ## 示例输出

    ❌ 发现问题：

    **关键：**
    1. 缺少使用说明 - 规范说"包含使用方法"，但文档中没有使用示例

    **重要：**
    2. 添加了未请求的功能 - 规范未请求高级配置，但创作者添加了
    3. 文件格式不对 - 规范要求 YAML 格式，但使用了 JSON

    **建议：**
    4. 缺少版本记录 - 建议添加更新日志部分
```
