# 内容质量审查者子代理提示模板

分派内容质量审查子代理时使用此模板。

```
任务工具（审查）：
  description: "审查任务 N 的内容质量"
  prompt: |
    你正在审查任务 N 的内容质量。

    ## 任务规范

    [来自计划的完整任务文本 - 粘贴在这里]

    ## 创作内容

    [创作者提交的内容摘要]

    ## 你的工作

    审查内容质量。假设内容已通过规范合规性审查（功能正确），现在检查质量：

    **内容质量：**
    - 标题和结构是否清晰？
    - 段落是否简短专注（单一主题）？
    - 是否有重复内容可以合并？
    - 术语是否一致？
    - 示例是否恰当？

    **可读性：**
    - 语言是否流畅？
    - 逻辑是否清晰？
    - 格式是否一致（标题、列表、代码块等）？
    - 是否有错别字或语法错误？

    **风格一致性：**
    - 内容是否遵循现有风格指南？
    - 语气是否与项目其他部分一致？
    - 是否使用了项目的惯用表达？

    **YAGNI：**
    - 是否有不必要的功能或复杂度？
    - 是否有"可能将来需要"的内容？
    - 是否有过度设计的迹象？

    ## 审查格式

    回报：

    **状态：** ✅ 批准 | ❌ 发现问题

    **优势：**
    列出内容做得好的地方（3-5 点）

    **如果发现问题：**
    按严重程度列出：
    - **关键** - 阻止进度，必须修复
    - **重要** - 应该修复，但可以讨论
    - **建议** - 改进建议，可选

    对每个问题：
    - 描述问题
    - 解释为什么是问题
    - 建议如何修复

    **如果批准：**
    确认内容质量良好，准备好交付。

    ## 严格但公平

    - 对质量严格 - 内容应该是可维护的
    - 对偏好宽容 - 区分"不同"和"错误"
    - 关注影响 - 标记真正重要的问题，不要微观管理

    ## 示例输出

    ✅ 批准

    **优势：**
    - 结构清晰，层次分明
    - 示例丰富且可操作
    - 语言简洁准确
    - 遵循项目风格指南

    ---

    ❌ 发现问题

    **优势：**
    - 内容完整
    - 覆盖所有需求

    **重要：**
    1. 术语不一致 - 有时用"技能"，有时用"Skill"，统一为"Skill"
    2. 缺少示例 - 使用说明部分没有实际示例，建议添加

    **建议：**
    3. 段落过长 - 第 3 节有 500 字连续段落，建议拆分
    4. 格式不统一 - 代码块有些有语言标识，有些没有
```
