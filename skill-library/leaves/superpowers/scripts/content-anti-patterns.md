# 内容创作反模式 (Content Creation Anti-Patterns)

**版本**: 1.0.0  
**适用**: Skill 创作、文档撰写、方案设计等创意项目

---

## ⚠️ 常见陷阱

创作内容时，避免这些常见错误。

---

## 1. 写完不测试

### ❌ 错误

```markdown
## 使用方法

```bash
./script.sh --do-something
```
```

**问题**：
- 命令是否真的能运行？
- 参数是否正确？
- 输出是否与描述一致？

### ✅ 正确

```markdown
## 使用方法

```bash
# 实际运行测试过
./script.sh --do-something
# 输出：Done!
```
```

**为什么更好**：
- 验证过命令有效
- 读者知道预期输出
- 有问题能及时发现

---

## 2. 假设读者有背景知识

### ❌ 错误

```markdown
配置 API Token 后运行脚本。
```

**问题**：
- 在哪里配置？
- 如何获取 Token？
- 配置后需要重启吗？

### ✅ 正确

```markdown
## 配置 API Token

1. 获取 Token：访问 https://example.com 获取你的 API Token
2. 编辑配置文件：`vim ~/.openclaw/openclaw.json`
3. 添加 Token：
   ```json
   {
     "env": {
       "API_TOKEN": "your_token_here"
     }
   }
   ```
4. 保存后重新运行脚本
```

**为什么更好**：
- 步骤清晰可跟随
- 新手也能操作
- 减少疑问和错误

---

## 3. 缺少示例

### ❌ 错误

```markdown
支持多种文案风格，使用 --style 参数指定。
```

**问题**：
- 有哪些风格？
- 具体怎么写？
- 输出是什么样？

### ✅ 正确

```markdown
支持 4 种文案风格：

```bash
# 温馨风（默认）
./script.sh generate --work-id 1 --style warm

# 可爱风
./script.sh generate --work-id 1 --style cute

# 文艺风
./script.sh generate --work-id 1 --style artistic

# 故事风
./script.sh generate --work-id 1 --style story
```

输出示例：
```
标题：长乐 | 10 后小篆刻家的成长记录
正文：
🔸 作品信息
印文：长乐
...
```
```

**为什么更好**：
- 读者知道具体用法
- 有预期输出参考
- 减少试错成本

---

## 4. 术语不一致

### ❌ 错误

```markdown
第 1 段：创建一个 Skill
第 3 段：这个技能可以...
第 5 段：您创建的技能...
第 8 段：这个 Skill 的功能...
```

**问题**：
- Skill vs 技能混用
- 读者困惑是否同一概念
- 显得不专业

### ✅ 正确

```markdown
全文统一使用 "Skill"（或统一使用"技能"）
```

**为什么更好**：
- 术语一致
- 阅读流畅
- 专业可信

---

## 5. 结构混乱

### ❌ 错误

```markdown
# 使用方法
# 简介
# 配置
# 故障排除
# 功能列表
# 安装
```

**问题**：
- 顺序不合逻辑
- 读者找不到信息
- 显得随意

### ✅ 正确

```markdown
# 简介
# 快速开始
# 安装
# 配置
# 使用方法
# 功能列表
# 故障排除
# 常见问题
```

**为什么更好**：
- 符合读者思维流程
- 信息容易查找
- 结构清晰

---

## 6. 过度创作 (YAGNI 违反)

### ❌ 错误

```markdown
## 高级配置（99% 用户不需要）

### 自定义日志级别
### 手动指定临时目录
### 覆盖默认超时
### 配置重试策略
### 设置代理服务器
...（2000 字）
```

**问题**：
- 大多数用户用不到
- 增加阅读负担
- 掩盖重要内容

### ✅ 正确

```markdown
## 高级配置

> 以下配置仅适用于特殊场景，普通用户无需修改。

### 自定义日志级别

仅在调试时使用：
```bash
./script.sh --log-level debug
```

[查看更多高级配置 →](advanced.md)
```

**为什么更好**：
- 主文档简洁
- 高级内容单独存放
- 需要的人能找到

---

## 7. 没有版本记录

### ❌ 错误

```markdown
（没有任何更新历史）
```

**问题**：
- 读者不知道是否最新
- 无法追溯变更
- 升级时不知道改了什么

### ✅ 正确

```markdown
## 更新日志

### v1.0.0 (2026-03-22)
- ✅ 初始版本
- ✅ 支持 4 种文案风格
- ✅ 飞书多维表格集成
```

**为什么更好**：
- 读者知道版本
- 变更可追溯
- 升级有依据

---

## 8. 缺少故障排除

### ❌ 错误

```markdown
（没有故障排除部分）
```

**问题**：
- 遇到问题不知道怎么办
- 重复问相同问题
- 读者放弃使用

### ✅ 正确

```markdown
## 故障排除

### 问题：命令找不到

```bash
# 检查脚本是否可执行
chmod +x script.sh

# 检查路径
which script.sh
```

### 问题：配置不生效

```bash
# 检查配置文件格式
jq . ~/.openclaw/openclaw.json

# 检查环境变量
echo $API_TOKEN
```
```

**为什么更好**：
- 读者能自助解决问题
- 减少重复支持
- 提升使用体验

---

## 9. 示例不可运行

### ❌ 错误

```markdown
```bash
./script.sh --some-flag --another-flag
```
```

**问题**：
- 读者运行后发现报错
- 失去信任
- 不知道哪里错了

### ✅ 正确

```markdown
```bash
# 实际测试过的命令
./script.sh --do-something
# 输出：Success!
```

> 如果看到错误，检查 [故障排除](#故障排除) 部分
```

**为什么更好**：
- 示例可运行
- 有预期输出
- 有问题有指引

---

## 10. 没有目标读者

### ❌ 错误

```markdown
（内容既不适合新手，也不适合专家）
```

**问题**：
- 新手看不懂
- 专家觉得啰嗦
- 两头不讨好

### ✅ 正确

```markdown
> 本文档面向首次使用 Skill 的开发者。

如果你是有经验的 OpenClaw 用户，可以跳过 [简介](#简介) 和 [安装](#安装) 部分。
```

**为什么更好**：
- 明确目标读者
- 内容难度合适
- 读者知道是否适合自己

---

## 📋 创作前检查清单

开始创作前问自己：

- [ ] 我知道读者是谁吗？
- [ ] 我知道什么是"完成"吗？
- [ ] 我有成功标准吗？
- [ ] 我能验证内容正确吗？
- [ ] 我有相关示例吗？
- [ ] 我测试过示例吗？

---

## 📋 创作后检查清单

完成创作后问自己：

- [ ] 新用户能独立使用吗？
- [ ] 所有示例都能运行吗？
- [ ] 术语一致吗？
- [ ] 结构清晰吗？
- [ ] 有故障排除吗？
- [ ] 有版本记录吗？

---

## 🎯 黄金法则

**好的内容**：
- 读者能独立使用
- 示例都可运行
- 结构清晰易查
- 术语一致专业

**坏的内容**：
- 读者看不懂
- 示例运行报错
- 结构混乱难找
- 术语前后不一

---

**记住**：创作的目的不是"写完"，而是"有用"。内容再好，读者用不了就是零分。
