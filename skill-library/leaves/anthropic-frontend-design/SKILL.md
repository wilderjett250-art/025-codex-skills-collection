# Visual direction
Establish the actual audience, page job, content and supplied aesthetic constraints. Preserve existing product behavior and relevant design-system conventions. Do not invent client history, product claims or research.
Select one surface reference:
- [Product UI](references/product-ui-direction.md): dashboards, editors, admin and repeated workflows.
- [Landing composition](references/landing-page-composition.md): marketing, portfolios and image-led pages.
Read both only when the task includes both surfaces.
Define a compact direction using the needed type roles, spacing, color tokens and layout hierarchy. Make distinctive choices where the brief leaves room; a signature flourish or multiple font families is not mandatory for an operational screen.
Resolve navigation and error/recovery flows before visual polish; use interaction-design only if those decisions are actually open. Use the selected framework owner for implementation rather than mixing all framework rules here.
Read [Taste calibration](references/taste-review.md) only for deeper critique. Detailed prior writing/process advice is preserved under references/curation-20260908/; select one section when it resolves a concrete question. No circular loading through taste-skill.
Use real content, responsive layout, visible focus and reduced-motion behavior. Compare rendered results against the brief and verify the primary action. Favor evidence-backed changes over repeating self-critique without new findings.
